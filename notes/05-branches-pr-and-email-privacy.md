\# 05 分支、Pull Request 与邮箱隐私



\## 本次目标



理解 Git 分支、Pull Request、合并方式和提交邮箱隐私。



\## 分支



分支是指向某个提交的名称，不是项目文件夹的完整复制。



新任务可以在独立分支中完成，避免直接修改稳定的 `main`。



\## Pull Request



Pull Request 用于请求把一个分支中的修改合并到另一个分支。



创建 PR 后，可以在合并前检查：



\- 提交内容

\- 修改的文件

\- 自动检查结果

\- 是否存在冲突

\- 是否包含隐私或密钥



\## 三种合并方式



\### Merge commit



保留分支中的原始提交，并额外创建合并提交。



\### Squash and merge



把分支中的多个提交压缩成一个新提交后放入 `main`。



\### Rebase and merge



保留每个提交的独立变化，但把它们重新放到 `main` 最新位置后面，提交编号通常会改变。



\## 分支清理



PR 合并后：



1\. 删除 GitHub 上的远程任务分支

2\. 使用 `git fetch --prune origin` 清理本地远程记录

3\. 切换并更新本地 `main`

4\. 使用 `git branch -d` 删除已合并的本地分支



\## 邮箱隐私



GitHub 提交中会保存作者邮箱。



为了避免公开个人邮箱，Windows Git 已配置为使用 GitHub 提供的 `noreply` 邮箱。



以前的提交不会因为修改配置而自动改变，新的配置只影响之后创建的提交。

## 我的理解

分支用于隔离尚未完成的任务，`main` 用于保存已经检查和整理好的稳定成果。

Pull Request 不只是一个合并按钮，它还保存了修改原因、讨论、检查结果和合并记录。

公开仓库前，需要检查提交邮箱、密钥、隐私、大文件和内容许可证。
